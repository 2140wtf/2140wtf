## Summary

Added defense-in-depth URL validation at media-component boundaries, hardened sandboxed iframe bridge scripts to target a specific parent origin and reject cross-origin messages, added a `sandbox` attribute to the YouTube embed, tightened the CSP, and validated push-notification payload URLs in the service worker.

## Changes made

### 1. Media component URL validation
All components now call `sanitizeUrl()` at their public boundary and drop unsafe inputs instead of letting them reach `<img src>`, `<video src>`, `<audio src>`, or `<AvatarImage src>`.

- **VideoPlayer.tsx** — sanitizes `src` and `poster` before passing them to HLS/Blossom fallback logic and the Media Session API.
- **AudioVisualizer.tsx** — sanitizes `src` and `avatarUrl`.
- **ImageGallery.tsx** — builds a `safeImages` array via `useMemo`; malformed/ non-HTTPS URLs are filtered out before grid and lightbox rendering.
- **CustomEmoji.tsx** — `CustomEmojiImg` returns `null` if the emoji URL is not HTTPS.

### 2. Sandbox bridge script hardening
Bridge scripts that run inside `SandboxFrame` iframes previously posted to `'*'`. They now derive the expected parent origin from `document.referrer` and:
- Send `postMessage(..., parentOrigin)` instead of `'*'`.
- Drop incoming messages whose `event.origin` does not match `parentOrigin`.

Files:
- `src/lib/nsiteNostrProvider.ts` (NIP-07 provider injected into nsite iframes)
- `src/components/Webxdc.tsx` (`window.webxdc` bridge for mini-apps)

### 3. YouTube embed sandboxing
- **YouTubeEmbed.tsx** — added `sandbox="allow-scripts allow-same-origin allow-popups allow-presentation allow-fullscreen"` for parity with other external embeds.

### 4. Content-Security-Policy tightening
- **index.html** — added `form-action 'none'; upgrade-insecure-requests;` to the meta CSP.

### 5. Service worker push payload validation
- **public/sw.js** — added `isSafeNotificationUrl()` helper. `icon` and `badge` must be same-origin or HTTPS; otherwise they fall back to `/icon-192.png`. `title` and `body` are truncated to safe lengths.

### 6. Adversarial URL tests
- **New file:** `src/lib/sanitizeUrl.test.ts`
- Covers valid HTTPS, `javascript:`, `data:`, `http:`, protocol-relative, malformed, and null/undefined inputs.

## Notes / future work

- The Pets SVG pipeline (`src/pets/ui/*SvgRenderer.tsx`) remains disabled/gated. If enabled, it should be reviewed separately because `sanitizePetsSvg` allows `<style>`, SMIL, and `@keyframes`.
- `frame-src 'self' https:` remains broad by design because 2140.wtf embeds arbitrary HTTPS content (relays, media, external social cards). A stricter policy would require a build-time allowlist of canonical relay/media origins.
