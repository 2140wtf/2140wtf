## Summary

Hardened the supply chain and build tooling: aligned on a single lockfile, removed lockfile-bypassing `npm install` from npm scripts, patched known vulnerable dependencies, fixed a dev-only path-traversal vector in the Vite `PUBLIC_DIR` plugin, restricted `DITTO_CONFIG_FILE`, made the bundle analyzer opt-in, and added checksum verification for CI-downloaded binaries.

## Changes made

### 1. package.json — lockfile discipline
- Removed `npm i --silent` from `dev`, `build`, and `test` scripts so local/CI builds respect the lockfile.
- Added an explicit `ci` script: `npm ci && npm run test`.

### 2. Lockfile unification & dependency updates
- Deleted the stale/secondary `pnpm-lock.yaml`.
- Regenerated `package-lock.json` from scratch.
- Resolved versions now include the patched releases:
  - `vite@8.0.16` (was 8.0.7, fixes `server.fs.deny` bypass & NTLM hash disclosure)
  - `dompurify@3.4.11` (was 3.4.0, fixes multiple XSS/config-pollution advisories)
  - `tar@7.5.16` (was 7.5.11, fixes PAX size-override smuggling)
  - `js-yaml@4.2.0` (was 4.1.1, fixes quadratic DoS in merge keys)
- `npm audit` now reports **0 vulnerabilities**.

### 3. vite.config.ts — build-time path safety
- Added `isWithinProjectRoot()` guard so `DITTO_CONFIG_FILE` cannot be used to read arbitrary files outside the repo at build time.
- Hardened the `PUBLIC_DIR` dev middleware against directory traversal (`..` / encoded variants) by resolving the requested path and verifying it stays under the configured public directory.
- Made `rollup-plugin-visualizer` opt-in via `ANALYZE=1`; the bundle breakdown (`dist/bundle.html`) is no longer emitted on every production build by default.

### 4. .gitlab-ci.yml — CI supply-chain integrity
- Changed the `test` job to `npm ci && npm run test` so CI uses the lockfile.
- `deploy-nsite`: pinned `nsyte` to `v0.27.0` and added SHA-256 verification (`8289ff33790332186124174cd647581ee604ada72e6cd202279e0087bf2bebdf`).
- `build-apk`: added SHA-256 verification for the Android cmdline-tools zip (`2d2d50857e4eb553af5a6dc3ad507a17adf43d115264b1afc116f95c92e5e258`).
- `publish-zapstore`: pinned `zsp` from `@latest` to `@v0.4.11` (Go module proxy checksum verification applies).

### 5. TypeScript compatibility fixes exposed by dependency refresh
- `AudioVisualizer.tsx`, `usePushNotifications.ts`: cast/generated `Uint8Array`s to `Uint8Array<ArrayBuffer>` to satisfy stricter DOM typings.
- `useNostrifiedEvents.ts`, `src/lib/nostrPush.ts`: `nostr-tools` `SimplePool.subscribeMany` now expects a single `Filter`; removed unnecessary array wrappers.
- `useZaps.ts`: fixed `makeZapRequest` to use `pubkey` (not `profile`) and branch correctly between addressable-event and profile-only zap requests.

### 6. ESLint regression fix
- Added a file-level disable for `react-refresh/only-export-components` in `src/lib/sidebarItems.tsx` (a config/registry file that exports helper functions/constants alongside components); restores 0-warning baseline after `eslint-plugin-react-refresh` upgrade.
