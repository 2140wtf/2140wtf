## Bugs fixed

| File | Problem | Fix |
|------|---------|-----|
| `src/hooks/useZaps.ts` | Double-click could fire two `zap()` calls before `isZapping` state flushed. | Added `zapInFlightRef` guard that rejects concurrent invocations and resets in `finally`. |
| `src/hooks/useZaps.ts` | No comment length limit; zap comment could be arbitrarily large. | Added `MAX_ZAP_COMMENT_LENGTH = 1000` validation with toast error. |
| `src/hooks/useZaps.ts` | No upper bound on zap amount; `amount * 1000` could exceed `Number.MAX_SAFE_INTEGER` as millisats. | Added `MAX_ZAP_AMOUNT_SATS = floor(MAX_SAFE_INTEGER / 1000)` guard. |
| `src/hooks/useZaps.ts` | LNURL callback `fetch` had no timeout and could hang indefinitely. | Wrapped fetch in `AbortController` with 30 s timeout. |
| `src/hooks/useZaps.ts` | Raw HTML error pages from LNURL providers could be echoed into toast. | Truncated fallback reason to 500 chars. |
| `src/hooks/useCashuWallet.ts` | `sendToken`, `payInvoice`, and `mintFromQuote` had no mutex; concurrent calls could double-spend proofs or double-mint. | Added per-operation FIFO mutexes (`sendTokenMutexRef`, `payInvoiceMutexRef`, `mintFromQuoteMutexRef`) with a shared `acquireMutex` helper; released in `finally`. |
| `src/hooks/useNWC.ts` | NWC URI parser only checked prefix; empty/whitespace/junk URIs accepted; protocol log could include secret-bearing split. | Trim input, validate protocol without re-logging URI, reject length `< 10` or `> 4000`. |
| `src/hooks/useNWC.ts` | `sendPayment` created `LN` client synchronously without timeout or secret sanitization. | Added 5 s timeout around client creation and redact `nostr+walletconnect://…` from error messages before throwing. |
| `src/lib/marketplace.ts` | Zero/negative/non-finite listing prices were accepted; BTC values could round to 0 sats and still be offered for checkout. | Reject `value <= 0` and non-finite; reject conversions that produce `<= 0` sats or non-positive USD. |
| `src/components/LightningInvoiceCard.tsx` | `parseBolt11Amount` mis-classified amountless invoices (`lnbc1…`) as 100 M sats. | Extracted parser to `src/lib/bolt11.ts`, made amount group optional, return `null` for amountless HRP. |

## Recommendations for Phase 5

1. **Cashu mint health & failover** — Add explicit mint availability checks and automatic failover when the selected mint is offline, with user-visible status indicators.
2. **NWC permissions handshake** — Replace the constructor-only "test" in `addConnection` with a real `getInfo()` call and validate returned `methods` include `pay_invoice`; surface budget/expiration info.
3. **Pending melt reconciliation robustness** — Test and harden the pending-melt poller: ensure `restoreMeltInputProofs` handles seed-unavailable edge cases and that polling stops cleanly on unmount.
4. **Cashu receive/send end-to-end tests** — Add Vitest tests that mock `@cashu/cashu-ts` to exercise proof recovery, double-spend handling, and timeout recovery paths in `useCashuWallet`.
5. **Zap polling / proof-of-payment** — Add post-payment polling for NWC/WebLN zaps so the UI confirms settlement rather than assuming success after `sendPayment` returns.
6. **Input sanitization** — Audit all places where external invoice strings, LNURLs, and NWC URIs are interpolated into error toasts/logs to ensure no secret leakage remains.
