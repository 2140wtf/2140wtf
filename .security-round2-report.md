## Summary

Removed a hardcoded third-party API key, expanded secret redaction across Sentry and payment error paths, sanitized user-facing zap error toasts, added insecure-randomness warnings, and added a console warning when sensitive values are written to plaintext web `localStorage`.

## Changes made

### 1. Tenor API key moved out of source
- **File:** `src/hooks/useGifSearch.ts`
- Replaced the hardcoded `TENOR_API_KEY` literal with `import.meta.env.VITE_TENOR_API_KEY`.
- Throws a clear error at runtime if the key is missing, preventing silent broken GIF search.
- **File:** `.env.example`
- Added `VITE_TENOR_API_KEY=""` with placeholder.
- **Action required:** rotate the existing key in the Tenor/Google Cloud console and set the new value in deployment environments.

### 2. Centralized secret redaction helper
- **New file:** `src/lib/redactSecrets.ts`
- `redactSecrets(value)` redacts:
  - `nsec1…` private keys
  - `nostr+walletconnect://…` and `nostrwalletconnect://…` URIs
  - `bunker://…` URIs
  - 64-character hex strings when the surrounding text contains private/secret/key/seed language
- `redactSensitiveData(value)` recursively walks Sentry-style payloads and replaces values for sensitive keys (`secret`, `privateKey`, `seed`, `proofs`, etc.) with `[REDACTED]`.
- **New tests:** `src/lib/redactSecrets.test.ts` (8 tests).

### 3. Sentry `beforeSend` hardened
- **File:** `src/lib/sentry.ts`
- Replaced the single `nsec1` regex scrubber with the full `redactSensitiveData()` walker.
- Now redacts NWC URIs, bunker URIs, hex private keys, Cashu proofs/seed ciphertext, and any value keyed as secret/private/seed before transmission.

### 4. NWC error redaction reused
- **File:** `src/hooks/useNWC.ts`
- Replaced the inline NWC-URI regex with `redactSecrets()` so all secret patterns are covered consistently.

### 5. Zap error toasts sanitized
- **File:** `src/hooks/useZaps.ts`
- NWC/WebLN failure toasts no longer display raw provider error messages (which can leak invoice/routing hints or wallet metadata).
- User sees generic, safe messages; a redacted version is logged to the console for support/debugging.
- Outer `zap` failure catch also shows a generic message instead of the raw exception text.

### 6. Insecure-randomness warnings
- **Files:** `src/lib/uuid.ts`, `src/lib/cashu/storage.ts`, `src/hooks/useSavedFeeds.ts`
- Added explicit `console.warn()` when the `Math.random()` fallback is reached because `crypto` APIs are unavailable (insecure/non-secure contexts).
- Each fallback now documents that it is not suitable for cryptographic key material.

### 7. Plaintext web-storage warning
- **File:** `src/lib/secureStorage.ts`
- When the app runs on web (not Capacitor), `setItem` falls back to `localStorage`.
- For keys that look sensitive (`nsec`, `nwc`, `wallet`, `seed`, `cashu`, `proof`), a `console.warn()` explains that the value is being stored in plaintext and recommends the native app or an extension.

## Notes / future work

- Web localStorage encryption for nsec/NWC is not implemented in this round; it would require a passphrase prompt and a larger UX change. The warning and documentation are the immediate mitigations.
- The rotated Tenor key must be injected into `.env` / CI variables before the next deployment; the old literal should be considered compromised.
