## Executive summary

The audit moved from a broad reconnaissance phase into four remediation rounds. We fixed systemic supply-chain issues, removed a hardcoded API key, hardened secret redaction in telemetry and payment error paths, added defense-in-depth URL validation at media boundaries, tightened iframe sandboxing and CSP, validated push payloads, and added adversarial tests for Bitcoin PSBTs, NWC URIs, Cashu storage/mutexes, silent payments, and zaps. Two functional bugs were found and fixed during the intrusion-test round.

## Remaining risks / recommended future work

1. **Web localStorage encryption** — nsec/NWC/Cashu secrets are still plaintext in web `localStorage`. A proper fix requires passphrase-based encryption and UX changes; warnings were added as an immediate mitigation.
2. **Pets SVG sanitizers** — `sanitizePetsSvg` has a broader allowlist than `sanitizeSvg` (styles, SMIL). Pets remains gated off, but a dedicated review is needed before launch.
3. **End-to-end Cashu concurrency** — the FIFO mutex is covered in isolation, but a full hook-level concurrency test with mocked mint network would add confidence.
4. **CSP `frame-src`** — kept as `https:` because 2140.wtf embeds arbitrary HTTPS content. A build-time allowlist could tighten this for specific deployments.
5. **Android/iOS native surface** — FileProvider paths, backup rules, and native permission flows were noted but not changed in this web-focused pass.
6. **CI runner isolation** — the self-hosted macOS runner for iOS builds is a supply-chain risk; ephemeral/isolated runners and credential rotation are recommended.
