This round focused on adversarial unit tests for Bitcoin PSBT signing, NWC URI validation, Cashu storage/mutexes, silent-payment decoding, and the zap flow. A few small, safe bugs were fixed; no interfaces were changed.

## 1. Bitcoin / PSBT Hardening

**Files:** `src/lib/bitcoin.ts`, `src/lib/bitcoin.test.ts`, `src/lib/bitcoin-signers.ts`

### Tests added (`src/lib/bitcoin.test.ts`)

- `rejects a non-P2TR input (missing tapInternalKey)` — proves `inspectPsbtForLocalSigning` refuses non-Taproot inputs.
- `rejects SIGHASH_SINGLE` — bad sighash flag rejected.
- `rejects SIGHASH_ALL | ANYONECANPAY (0x81)` — only `DEFAULT`/`ALL` are accepted.
- `zeroizes the private key after a successful signing` — verifies `signPsbtLocal` wipes the decoded secret.
- `zeroizes the private key even when signing fails` — wipe still happens on error paths.

(Existing tests already covered wrong-owner pubkey, outputs exceeding inputs / negative fee, and fee-rate caps.)

### Bugs fixed

- None in `bitcoin.ts`; the existing guards already rejected every adversarial case. The only surprise was that `@scure/btc-signer` does not export `SigHash.ANYONECANPAY`, so the test uses the raw bitmask `0x81`.

## 2. NWC / Lightning URI Validation

**Files:** `src/hooks/useNWC.ts`, `src/hooks/useNWC.test.ts`

### Tests added (`src/hooks/useNWC.test.ts`)

- `accepts a valid nostr+walletconnect:// URI with pubkey and relay`
- `accepts the alternate nostrwalletconnect:// spelling`
- `rejects a URI missing the pubkey query parameter`
- `rejects a URI missing the relay query parameter`
- `redacts the NWC secret from connection-failure toast messages`

### Bugs fixed

- **`src/hooks/useNWC.ts`:** The old `parseNWCUri` only validated the protocol and length. Added a new exported `validateNwcUri` that requires non-empty `pubkey` and `relay` query parameters.
- **`src/hooks/useNWC.ts`:** Error logging/toasting in `addConnection` and `sendPayment` now runs `redactSecrets` on messages before they reach the console or UI, preventing NWC connection secrets from leaking in error text.

## 3. Cashu Race & Storage

**Files:** `src/lib/cashu/storage.ts`, `src/lib/cashu/storage.test.ts`, `src/hooks/useCashuWallet.ts`, `src/hooks/useCashuWallet.test.ts`

### Tests added

`src/lib/cashu/storage.test.ts`:
- `generates a crypto.randomUUID id by default`
- `falls back to Math.random when crypto.randomUUID throws`
- `appends a timestamp when a generated id collides with an existing transaction`

`src/hooks/useCashuWallet.test.ts`:
- `queues concurrent callers so only one runs at a time` — FIFO mutex test.
- `allows sequential callers to acquire and release independently`

### Bugs fixed / improvements

- **`src/hooks/useCashuWallet.ts`:** Moved the generic `acquireMutex` helper to module scope and exported it so it can be unit-tested in isolation. The hook continues to use it for `sendToken`, `payInvoice`, and `mintFromQuote`, so the serialization behavior is unchanged.

### Future work

- A full end-to-end concurrency test for `sendToken` / `payInvoice` / `mintFromQuote` through the hook would require extensive mocking of `@cashu/cashu-ts` and the mint network; the mutex primitive is now covered directly instead.
- No raw Cashu proof/seed strings were found in the storage-layer error paths; existing helpers already avoid interpolating secrets into thrown messages.

## 5. Zap Hardening

**Files:** `src/hooks/useZaps.ts`, `src/hooks/useZaps.test.ts`

### Tests added (`src/hooks/useZaps.test.ts`)

- `does not call makeZapRequest for non-positive amounts`
- `rejects amounts above the safety cap`
- `rejects comments exceeding the max length`
- `blocks concurrent zap attempts with the in-flight guard`
- `calls makeZapRequest with the target pubkey and no event for regular events`
- `calls makeZapRequest with event for addressable targets (30000-39999)`

### Bugs fixed

- **`src/hooks/useZaps.ts`:** `zapInFlightRef` was set to `true` before checking `user`, `target`, `author`, lightning address, and zap endpoint, but the early-return branches only reset `isZapping` and left the ref stuck at `true`. This permanently blocked all future zap attempts after any of those error paths. Fixed by resetting `zapInFlightRef.current = false` (and `setIsZapping(false)`) on every early return.
